# Архитектура проекта Karcas MK2

Документ описывает внутреннее устройство генератора расчетных схем **Karcas MK2**, структуру данных конечных элементов, алгоритмы предотвращения геометрических коллизий и специфику гибридного кодирования текстовых файлов для **ЛИРА-САПР 2024 R2.3**.

---

## 1. Общие архитектурные принципы

* **Zero-Dependency & Offline-First:** приложение полностью написано на нативном ES6+ JavaScript без использования сборщиков (Webpack/Vite) и внешних библиотек. Все ресурсы подключаются локально, что гарантирует стабильную работу по протоколу `file://` без ошибок CORS.
* **Реактивная пересборка модели:** любое изменение параметров в DOM (`oninput`, `onchange`) вызывает функцию `generateModel()`, которая заново строит топологию узлов и стержней, обновляет статистику, перерисовывает 3D-сцену и актуализирует предпросмотр выходного кода.
* **Персистентность сортамента:** пользовательская база жесткостей хранится в `localStorage` под ключом `lira_karcas_profiles_v23` и автоматически нормализуется при инициализации.

## 3. Ключевые подсистемы

### 3.1. Управление ярусами и предотвращение дублирования элементов
Массив `columnTiers` хранит объекты ярусов формата:
```javascript
{ h: Number, profIdx: Number, tieY: Boolean, tieX: Boolean }
```
* Каждый ярус `t` формирует горизонтальную плоскость на отметке `zLevels[t + 1]`.
* Продольные распорки (`role: 'tieY'`) генерируются вдоль оси Y при `tier.tieY === true`.
* Поперечные распорки (`role: 'tieX'`) генерируются вдоль оси X при условии `tier.tieX && !(isTop && hasTruss)`. Проверка `!(isTop && hasTruss)` исключает создание дублирующих стержней на верхней отметке `H`, где геометрию вдоль оси X уже формирует нижний пояс стропильной фермы.
* В интерфейсе `renderTiers()` синхронно блокирует чекбокс `X` верхнего яруса при активном флаге `hasTruss`.

### 3.2. Дедупликация узлов и нумерация жесткостей
* **Узлы (`getNodeId`):** координаты переводятся в целочисленные десятые доли миллиметра (`Math.round(coord * 10000)`) и используются как строковый ключ `kx_ky_kz` в `Map`. Это гарантирует совпадение узлов примыкания ферм, распорок, колонн и связей без образования «висячих» узлов.
* **Жесткости (`getStiffIdx`):** в выходной файл попадают только те профили из `PROFILES_DB`, которые реально задействованы в текущей схеме, со сквозной нумерацией `1..N`.

### 3.3. Нормализация базы профилей (`normalizeProfile`)
Исходный массив `INITIAL_PROFILES_RAW` содержит кортежи вида:
`[category, displayName, lira3Geometry, engSectionType, srtFileName, shapeSize, extraParams]`

При загрузке выполняется:
1. Безопасная распаковка через деструктуризацию массива.
2. Санитизация строки типоразмера (`shapeSize`): замена кириллических символов `х`, `Х` и знака умножения `×` на латинскую `x` (`/[хХ×]/g -> 'x'`), что предотвращает ошибки поиска профиля в сортаментах `.profiles.srt` при импорте в ЛИРА-САПР.

## 4. Формат выходного файла ЛИРА-САПР 2024 R2.3

Генератор формирует текстовый файл для **признака схемы 5** (пространственная стержневая система, 6 степеней свободы):

| Блок | Назначение | Особенности реализации |
| :--- | :--- | :--- |
| `( 0/` | Заголовок задачи | Имя задачи очищается от пробелов и кириллицы (`cleanTaskName`) для совпадения с именем `.txt` файла. |
| `( 1/` | Топология стержней | Все элементы задаются типом КЭ `10` (универсальный пространственный стержень). |
| `( 2/` | Шарниры в узлах | Записываются по степеням свободы `5` (`UY`) и `6` (`UZ`) для 1-го и/или 2-го узла стержня (`id 1 5 0/ id 1 6 0/`). |
| `( 3/` | Численные жесткости | Геометрические характеристики сечений (`EF`, `EIy`, `EIz`, `GIk`) без префикса бруса `S0`. |
| `( 4/` | Координаты узлов | Координаты `X Y Z` в метрах. |
| `( 5/` | Граничные условия | Жесткая заделка опорных узлов (`z === 0`) по всем 6 направлениям (`1 2 3 4 5 6`). |
| `( 9/` | Местные оси стержней | Угол поворота сечения колонн (`colAngle`) вокруг продольной оси. |
| `{13/` | Привязка к сортаменту | Метаданные стальных профилей (`Section`, `MatId = STL`, `File`, `Shape`) для проверок в ЛИРА-СТК. |

## 5. Гибридное кодирование при экспорте (`downloadTxt`)

ЛИРА-САПР 2024 R2.3 предъявляет разные требования к кодировке основной расчетной части и секции металлопроката `{13/`:
1. Текст разбивается по маркеру `{13/`.
2. **Первая часть (`( 0/` — `( 9/`):** кодируется побайтово в **`Windows-1251`** функцией `encodeWindows1251()`.
3. **Вторая часть (`{13/` — `}`):** кодируется в **`UTF-8`** через стандартный `TextEncoder`.
4. Оба буфера `Uint8Array` объединяются в единый бинарный `Blob`, что обеспечивает корректное чтение кириллицы и символов сортамента при импорте.

## 6. 3D-визуализация на Canvas

* **Ортографическая проекция (`projectPoint`):** центрирование модели относительно габаритного центра `(midX, midY, midZ)` с последовательным поворотом вокруг вертикальной оси Z (`camAngleZ`) и наклоном (`camAngleX`).
* **Цветовая кодировка:**
  * `#3b82f6` (синий) — колонны;
  * `#14b8a6` (бирюзовый) — продольные распорки вдоль Y;
  * `#f97316` (оранжевый) — поперечные распорки/ригели вдоль X;
  * `#22c55e` (зеленый) — элементы стропильных ферм;
  * `#eab308` (желтый) — вертикальные и горизонтальные связи;
  * `#ef4444` (красный) — опорные узлы заделки.
* **Гизмо осей (`drawAxisGizmo`):** отрисовывает единичные орты `X` (красный), `Y` (зеленый), `Z` (синий) с наконечниками стрелок в левом нижнем углу холста через ту же матрицу проекции `projectPoint`, что и основная модель.
